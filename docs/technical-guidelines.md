# Technical guidelines

Established game-world facts and open questions live in [FACTS.md](../FACTS.md); keep technical details and implementation status in these guidelines or the README. Follow [the art direction](art-direction.md) for creative guidance, including its constraints on explicit dates and locations in visible and accessible interface text.

## Runtime and tooling

Next, Please! is a browser-only, client-side game. Vite and strict TypeScript produce static HTML, CSS, JavaScript, and local assets. There is no backend, account system, runtime API, CDN dependency, or remotely loaded font. The browser supplies Canvas 2D, file selection/download, and fullscreen support. Outside the game canvas, the page uses system monospace fonts.

Use Node 22.12+ on the Node 22 release line, Node 24, or Node 26+ to satisfy the current tooling. Install from the committed lockfile with `npm ci`. Keep runtime dependencies focused: `fflate` handles save compression; Howler handles local music and effects. Add libraries only when they solve an actual game requirement.

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the local development server. |
| `npm run build` | Type-check, then create the static `dist/` build. |
| `npm run preview` | Serve that build locally. |
| `npm test` | Run Vitest unit checks. |
| `npm run test:browser` | Run Playwright interface checks. |

## Display and input

- The desktop game canvas and its logical coordinate system are always **570 × 320**. Keep layout positions, hit areas, text, and sprite coordinates in native pixels. The separate mobile reception below does not resize or run the game canvas.
- Use Canvas 2D with image smoothing disabled. Use `image-rendering: pixelated` for display scaling. Do not increase the canvas backing resolution to match the window or device pixel ratio.
- `src/core/display.ts` chooses a whole-number CSS scale when the available space permits at least 1×. Center the frame and leave unused space around it rather than stretching its aspect ratio. Fullscreen follows the same rule.
- There is no text row above the frame. The lower row uses a 16px container (14px on small screens), compact 12px utility labels, 14px PL / EN buttons, and 16px Menu / Saves buttons, and native DOM controls. Measure its actual wrapped height when fitting the frame, including fullscreen; language changes must also trigger fitting.
- Below native resolution, fractional fitting keeps the interface visible. Uneven or lost pixels are unavoidable at this size. Browser zoom and fractional device pixel ratios can also affect physical pixel alignment.
- Canvas-rendered controls have transparent semantic DOM buttons or links over the same native rectangles. Preserve keyboard focus, accessible names, tab order, and visible focus indicators. Keep these in-scene DOM controls and canvas inside the same scaled stage. Language, fullscreen, music, and cabinet menu/save controls live outside the stage in the lower page row. Utility controls remain visible in fullscreen; credits, archive, restart and drawer dialogs make them inert until closed.
- `src/render/font.ts` is the original bitmap font, with Polish diacritics. Glyph cells are 5 × 9, ordinary capitals use the bottom seven rows, spaces are three pixels wide, and the gap between characters is one pixel. Multiline advance is twelve pixels. The separate document face preserves mixed case in a seven-pixel cell, with five-pixel capitals, a four-pixel lowercase x-height, variable-width glyphs, Polish accents, and eight-pixel line advance. Use `drawDocumentText`/`measureDocumentText` for paperwork and the rulebook, retaining the established title face. Measure text before placing it; never scale a label fractionally to make it fit.
- The pixel cursor is generated locally in `src/core/display.ts`; keep a browser cursor fallback.

## Mobile reception

`src/main.ts` evaluates `detectMobileDevice()` from `src/core/device.ts` once, then lazily imports `src/mobile.ts` and `src/desktop.ts` as their views become needed. A mobile user-agent or User-Agent Client Hints flag, a Mac-identifying multitouch device, or a coarse pointer with no hover on a screen whose short side is at most 1100 and long side at most 1500 selects the mobile route. Keep the device decision for the page lifetime, so rotating a real phone does not reveal the game. In addition, `isMobileViewport(width, height)` selects the reception whenever the browser window is at most 900 CSS pixels wide and its width is at most 85% of its height, regardless of device or pointer. Reevaluate this condition on resize.

The mobile route is a responsive, full-screen DOM reception with a generated 320 × 480 handset illustration. Separate 260 × 132 dialogue and 280 × 260 note canvases composite generated local artwork and localized bitmap text with smoothing disabled. Integer text positions and whole-number overlay enlargement preserve the pixel lettering; overlays shrink only when 1× cannot fit between the controls. The upward speech tail at native (67, 0) follows the handset upper grille at (128, 92), accounting for portrait cover cropping and landscape contain positioning. Clamp the balloon within the space between the toolbar and footer. The handset fills the available mobile scene; compact landscape and portrait layouts keep the controls accessible. Starting in the reception does not import desktop gameplay, its artwork, save handling, or the music manifest. On a desktop, widening the window lazily initializes the game. Thereafter the two DOM roots are retained, with the inactive root hidden and inert; switching views does not reload the page or reset game state or the call. Serialize lazy imports and recheck the current dimensions before activating a view. The desktop canvas and its integer fitting remain unchanged.

`src/mobile.ts` owns the temporary five-step sequence: exchange tone, dialing, greeting, reply, note. Four activations advance it. Tapping anywhere in the scene also advances, with a one-second cooldown after every advance for scene taps. The native **Next** button bypasses that cooldown; language and sound controls do not advance the call. Holding a key must not skip through steps. The Polish dialogue is “Przychodnia słucham!” followed by “Praca zdalna? Doktor raczy żartować. Czekamy w placówce”. The final note carries the game title and the desktop requirement. All text, accessible names and English equivalents live in `src/i18n.ts`. The shared original bitmap font supplies the note's muted blue handwriting, with deterministic slant and baseline variation in `src/render/mobile.ts`; generated artwork contains no localized words. Keep complete dialogue text accessible, announce step changes, and move focus to the final note. PL / EN use 64 × 60 native buttons with the title bitmap font at 3×, and Next uses a 224 × 76 button with 4× lettering. The 36 × 36 sound icon uses generated 18 × 18 on/off sprites inside a 64 × 60 semantic button. Show exchange and dialing captions only while muted, with 3× bitmap lettering and localized word wrapping. The untaped note uses 4× title and 3× body handwriting; both dictionaries reflow the full copy into seven lines. Keep the mobile header free of a game title and omit its creator footer; Robert Chaba's credit and link remain in desktop credits and project metadata.

Only existing locale, mute and music-volume preferences are read or written. The call step and all other presentation data stay in memory; the reception creates no game state or save. An already initialized desktop retains its state in memory. The mobile audio manager registers only `phone-tone` and `phone-dial`. An unmuted click or keyboard activation unlocks Howler; enable sound to hear the initial exchange tone; tapping the receiver advances to dialing. The one-second tone loops seamlessly; the 3.9-second rotary sound plays once on the dialing step. Stop both effects on mute, hidden pages, `pagehide`, or transition into dialogue and the note. `stopSound(id)` unloads to cancel pending requests; delayed decoding must not replay an old step. No music plays on this route. `setDesktopActive(false)` cancels a carried item back to its prior position, pauses patient/clock/typewriter updates and music, stops effects, and disables global game shortcuts. Loaded music keeps its track position; a pending music load is cancelled and can be retried after a later desktop gesture. Returning restores the prior control focus and refits the desktop; each view rereads preferences when activated. Phone effects stop when its view is deactivated. See [the mobile artwork record](art-mobile-2026-10-25.md) and [audio provenance](../public/assets/audio/README.md).

## State, scenes, and localization

The current build includes the title screen, credits, preferences, a four-card illustrated introduction, daily cabinet shifts with 78 characters, illustrated domestic/weekend/departure scenes, and progress import/export. Start enters the introduction; later visits to the menu offer Resume. The office initially has no patient. The cabinet has four physical areas separated at x = 204–209 and y = 128–137: a 204-pixel left side for the patient and exchange shelf, and a 360-pixel right side for examinations and the main desk. The lower desktop areas are 182 pixels high. These separators are part of the artwork, with no section captions.

Pure transitions live in `src/core/game.ts`; the stable case catalog and seeded queue generation live in `src/core/patients.ts`, while `src/core/economy.ts` calculates settlement; `src/scenes/shift.ts` presents them; `src/render/clinic.ts` loads and composites the local generated illustrations, cabinet, and sprites. `src/core/desk.ts` owns pure item-position and stacking-order helpers; `src/core/desk-input.ts` translates mouse, touch, and keyboard input into logical-pixel movement. `src/desktop.ts` owns scene transitions, temporary selected and carried items, desk layout, typed-text and patient-animation updates, and DOM integration. Keep scene transitions, simulation state, input handling, and drawing separate. Render from current state; drawing must not change game state, call `Date.now()`, or generate new random values. Advance time and randomness during explicit updates, and retain any values needed for reproducible saves. Avoid a framework or general scene engine until concrete scenes need it. The analog clock takes persisted integer `clockMinutes` (07:57 arrival, 08:00 opening, 14:00 admissions cutoff and 17:15 final closing). Handling, page turns, stamps and decorative actions cost one minute; general examination, vision, pressure, and body measurement tests cost three, three, four, and two minutes, including repeated tests. Returning a certificate costs one minute. Calls are rejected from 14:00 onward. An admitted patient remains actionable after 14:00 and the clock continues advancing. Crossing 17:00 queues the localized cleaner call and its short balloon. Reaching 17:15 aborts the current action and any unfinished visit, removes the active certificate from clip groups and settles from the preceding state without a patient bonus or decision consequence; existing notes and referrals remain. The saved home clock preserves overtime instead of rewinding to 14:00. Returning the last certificate at closing or queue exhaustion settles the day immediately; the view completes the patient departure before showing home, without a bell activation. Explicit end-day remains available for an empty, finished office. A temporary 800 ms transition supplies fractional display time to the hour and minute hands (there is no second hand); it pauses when hidden or covered, and reduced motion shows the saved time immediately. The independent elapsed clock in `src/core/clock.ts` accumulates monotonic `performance.now()` deltas supplied by the controller: 30 real seconds add 30 simulated minutes with an active visit or 5 without one. The controller samples every 100 ms and at actions/context changes, applying whole minutes through pure `advanceClinicTime`; it retains the fractional remainder across actions, rate switches and pauses. Reading, carrying, pointer movement, patient animation and an open drawer keep the simulation running. Menus, hidden tabs, intro/home and the mobile reception pause it without later catch-up. Reduced motion changes only presentation. New days, restarts and successful imports reset the unsaved sub-minute remainder; failed imports preserve it. Ordinary elapsed ticks update the clock and accessible description without replacing controls or stealing focus. The admission cutoff, cleaner warning and final closing apply equally to elapsed time and action costs. See the save contract for exact time transitions.

Polish is the default locale; English is equally supported. All user-facing text, accessible names, status messages, and errors belong in the typed dictionaries in `src/i18n.ts`. Keep both languages' keys and meaning aligned. Render the same artwork for both locales, with text drawn separately, except for the four generated PL/EN decision impressions and the generated eye chart’s fixed optotypes. Decision words also belong in the dictionaries and accessible descriptions. The chart’s six language-independent letter rows are recorded in both dictionaries and baked into the background with their paper and rails, without runtime text overlays; its localized semantic examination control retains its original bounds. See [the eye-chart artwork record](art-eye-chart-2026-10-25.md). Check Polish diacritics and the longest labels at native resolution.

Only locale, mute, and music volume preferences use `localStorage`. Music volume defaults to 40%; missing or invalid stored volume falls back to that default. Volume and mute remain independent. Storage may be blocked or unavailable, so preference reads and writes must remain optional. Gameplay progress is an explicit export/import operation, not browser storage.

## Staff room and archive

The cabinet's Menu button and Escape (after canceling a carried item or closing the book) open the staff-room scene. It pauses elapsed game time, clock interpolation, patient motion and speech while keeping the current appointment, placed items, stacking and open book/page in memory. Resume or Escape returns to the same cabinet. Music continues. The room uses the same two-line Next, Please! lettering as the welcome screen, without a visible room caption or explanatory copy. Its accessible description still conveys the scene and pause state. The room offers Resume, Saves, Start over and Credits. Start over opens a keyboard-accessible confirmation with initial focus on cancellation; confirmation creates the initial first-day introduction and clears temporary presentation state while preserving locale, mute and volume. An older pending import is invalidated so it cannot overwrite the new game.

The archive uses a separate medical-secretary scene with Export, Import and Back controls. Opening it from the staff room or restart confirmation returns to that same screen; resuming after an import follows the loaded phase. Save validation and the version 15 format also preserve stored paperwork, the daily queue, random state, insurance and settlement. Both new scenes have local 570 × 320 artwork, localized text and controls on the quiet left wall (x = 32–240), plus full accessible scene descriptions. Credits, archive and restart confirmation trap keyboard focus and make outside utility controls inert; Escape closes them.

## Portable saves

`src/core/save.ts` owns the versioned gzip JSON format and file operations. `fflate` compresses version 15 saves into `.npsave` files. See [save-format.md](save-format.md) for the envelope, limits, error codes, and migration rules.

Treat imports as untrusted data. Validate the entire file before replacing live state; failed imports must preserve the current state, including the temporary desk layout, patient movement and speech. A successful import restores the saved appointment, resets item positions, stacking order and the book page, and clears carried items, selected tools, clock interpolation, patient movement and speech. Keep stable error codes in the save layer and translate their presentation in the interface. Export plain game data only: no DOM nodes, audio objects, functions, or temporary presentation state. Version 4 introduced small action costs. Version 5 added body measurements and persistent paperwork. Version 6 makes certificate intake explicit with `visit.certificateTaken`. Version 7 adds named certificates, supplementary annotations and paperclip bundles. Version 8 adds the separately stored manual and loose clips in `drawerItems`. Version 9 adds the saved random state, daily roster, insurance rate, daily consequences and home settlement. Version 10 adds previousMonthBalance, the larger catalog and weekend home days. Version 11 adds general examination results, numeric pressure/vision values and persisted examination order in visits and notes. Version 12 adds the first-two pressure history, latest actual pressure value, overtime clock, interrupted-visit validation and examinations before referral intake. Version 13 appends 25 portraits and 225 cases without changing the state shape. Version 14 permits identity-only notes without changing the state fields. Version 15 appends five authored identities per portrait and expands the case bound to 2502. Versions 1–14 retain strict legacy validation before explicit migration; imported 28-, 53- and 78-person queues remain unchanged until the next working day. Earlier clocks are preserved; subsequent actions use the new costs. Item coordinates, open book/page, selected tools, clock interpolation, patient movement and speech are presentation state, not save fields.

## Daily queues and settlement

`src/core/patients.ts` keeps 2,503 stable case IDs: 553 historical cases and 1,950 active cases for 390 identities sharing 78 portraits. IDs 0–102 retain their existing details and decisions; IDs 103–302 add eight variants for each of 25 new identities; IDs 303–327 append one general-examination concern for each of those identities. IDs 328–552 add nine cases for each of 25 further identities, without changing any earlier record. Separate catalogs define 45 jobs, 24 employers, 15 exposure tags, six work patterns and three active requirement profiles. Referrals and the manual identify WC/W/C requirements; general examination and body measurements are required in all profiles. A general concern always requires refusal; relevant vision/pressure findings otherwise determine the decision. The empty-hand patient control performs the general examination; the same portrait accepts a carried certificate for handoff. Numeric game tuning is explicit in the manual: a vision defect of absolute value 6 or greater in either eye is significant, pressure at systolic 160 or diastolic 100 requires refusal in pressure profiles, and systolic 180 or diastolic 110 is highlighted red. These are simplified fictional thresholds, not clinical guidance. No pilot cases or specialist consultations are implemented. See [patient-catalog.md](patient-catalog.md) for authoring contracts and deferred requirements. Each working day chooses one identity and case per portrait and randomizes the 78-person queue, including day one. Seeded replacements with existing fit variants of the same identity cap unfit patients at 25 of 78 (32.05%); advancing the next fit patient when needed keeps every queue prefix at or below 33%. Cases and examination criteria remain immutable. This balancing applies only to newly generated queues, not imported rosters. The constructor accepts an explicit seed for replay/tests and otherwise obtains fresh crypto entropy outside rendering. `GameState.roster` and `rngState` persist; drawing and accessible descriptions do not generate randomness. Old saves preserve their exact 28-, 53- or 78-person queue until the next working day.

`GameState.daily` tracks detected ZUS cases, employer complaints, fines and insurance increases. An incorrect approval is detected with probability 65%; a healthy refusal is detected with probability 75%, or 97% for managers. Each detected approval adds 100 zł for the first daily case and 400 zł thereafter. Each detected refusal raises the persistent insurance rate by 50 zł at the 300 zł base, otherwise 100 zł. At settlement, a day with no insurance increase lowers the rate by 50 zł, clamped to 300 zł, before charging that day's premium.

Returning a certificate after closing or queue exhaustion settles the day automatically. Explicit `end-day` is permitted only in an empty office after closing or queue exhaustion. It produces one persisted `DaySettlement` and moves the phase to `home`; repeated settlement actions cannot pay twice. Income is 1000 zł plus 50 zł per returned certificate. Living costs apply from day one and are one inclusive integer draw from 400 to 800 zł. After wages and ordinary costs, savings over 2000 zł permit an unexpected medicine, fur-coat, car-repair or home-repair expense; probability grows with savings and is capped at 85%. Current probability/cost formulas are implementation tuning in `src/core/economy.ts`, not additional narrative facts. Balances may be negative; no bankruptcy/story mechanic is added. Bribes and relationship-driven events remain deferred.

The home sequence composites generated local backgrounds with enlarged localized typewriter text: arrival, optional saved event, six-row budget and departure before the next workday. Budget rows are base income, patient bonus, previous-month carryover, living costs, fines and insurance; omit full expense formulas and event prices from visible and accessible copy. `previousMonthBalance` snapshots the balance when the calendar month changes; old saves initialize the unavailable historical amount to zero. Every home card uses `drawText`, the original welcome-screen face, without enlarging the compact document font. Titles and narrative text use integer 2× scale; budget text, amounts and action use native 1× scale. Home cards omit dates from both canvas and accessible text; the office calendar remains the date reference. Arrival continues with “Dalej” / “Continue”. The twelve arrival and twelve work comments use stable indices from saved `rngState` and day, without drawing randomness or changing state. Budget comments use one of three five-line pools for a positive, negative or zero daily balance change, independently of total savings; repainting, changing language and importing preserve the selected variant. Native-width wrapping keeps narrative lines inside 312 pixels and long amounts clear of budget labels; amounts end at x = 319, leaving more space before the illustration. The current page’s complete text and illustration description remain accessible while it types. Typing state stays outside drawing and saves; reopening a saved settlement starts its presentation at arrival without charging anything again. The home cursor advances every 24 ms with one local typewriter key at most per three characters; the intro retains 55 ms. Enter first reveals the page and then advances; held keys cannot skip cards. Menus/archive preserve the cursor, and reduced motion immediately reveals text. `next-day` is allowed only from home, preserves balance/insurance/paperwork, clears daily consequences, and snapshots monthly carryover on rollover. The provisional weekend model produces a settled home day with an empty queue, zero wages/bonuses and household costs, using a different budget illustration. Its saved expense may be a mountain/seaside trip, with no named destination. Monday generates a fresh 78-person queue and enters the cabinet at 07:57. Existing paid legacy weekend shifts remain importable. All gameplay state continues to use explicit gzip import/export; only preferences enter localStorage.

## Verification and deployment

Use Vitest for save round-trips, invalid imports, size limits, scaling behavior, and desktop movement bounds. Use Playwright for language switching, accessible controls, credits, save import/export, viewport changes, the illustrated intro, complete cabinet shifts, clock progression, decoration persistence, patient entry/exit, mouse/touch/keyboard item movement, and audio decode/mute. Check reduced motion, aligned moved hotspots, click-to-carry behavior, dedicated tool rests, early stamps, unstamped return rejection, and preservation of the live desktop after failed imports. Use Vitest for pure gameplay guards, deferred patient bonuses, detection thresholds, daily fine escalation, insurance decay, deterministic settlement, admission at closing, action costs and elapsed time, and nested save validation/migration as well. Add checks for meaningful behavior, not copies of the implementation. Run `npm run build` with the relevant tests before considering a change complete.

Deploy the contents of `dist/` to an HTTP(S) static host. Vite uses `base: './'` to support hosting under a subpath; resolve asset URLs accordingly. No server-side application or secrets belong in this project. Development and built output require a static server; double-clicking the source `index.html` is not a supported launch method. An offline cache or service worker is not part of the current foundation.

## Cabinet input and effects

Canvas-rendered items have aligned semantic buttons. Click or tap once to pick up a document, rubber stamp, or rulebook; the next click uses or places it. The carried item follows the pointer without holding a button, and the cursor is hidden over the stage. The left shelf shows compact papers and a closed book. Documents shrink on pickup: the incoming tray sheet becomes 28 × 66, and papers from either desktop become 48 × 64. This compact footprint stays fixed throughout pointer and keyboard movement; placement on the right expands the paper to 188 × 144. The temporary `DeskState.documentCarrySize` records this compact footprint and is cleared on placement or discarded on cancellation. The book shrinks to 64 × 36. Stamps retain their exception, growing from 36 × 36 in their holders to 48 × 48 in hand. Stamps have small dedicated rests at the far right and stay in hand after an impression or missed attempt. Coffee cup and pencil are absent. Hover and selection add no object outlines; the semantic DOM retains a keyboard-only focus indicator.

Keyboard users focus an item with Tab, lift it with Space, move it with arrows, use or place it with Enter or Space, and cancel with Escape. Arrows move four logical pixels, or twelve with Shift. Enter also retains focused item actions. The patient has a semantic certificate-handoff control; a carried document can be given through it by keyboard. Held objects can travel throughout the viewport, including over the patient; released items are clamped to one desktop with the appropriate footprint. Keyboard pickup preserves the paper or book center while shrinking, and placement centers the expanded object around its drop point before desktop clamping. Cancellation restores the prior position, open-book state and stacking order. Hit areas and stacking follow the same integer geometry as the artwork. Pickup and placement spend small amounts of time; pointer movement adds no action cost, while elapsed time continues.

Moving the referral out of the tray takes it. Once taken, the paper may be set down on either side. Only handing a stamped certificate to the patient's upper-left portrait ends the visit; the tray is storage. An unstamped handoff restores the document's previous position and keeps the visit active. All four examinations are available as soon as a patient has been called, including while the referral remains in its tray. Their results and first-performance order are retained, and blank desk notes bind automatically even before intake; later-fetched or retrieved blank notes receive the existing results. Certificate handling still requires referral intake, and either stamp may be applied before tests. Every returned completed and stamped certificate completes a visit and contributes 50 zł to the eventual daily bonus. Wrong decisions can trigger a detected complaint and financial consequence; missing examinations alone do not create a complaint from an inappropriate sender. The lamp and plant/certificate remain interactive, with localized feedback. No gameplay progress goes into browser storage.

The rulebook is a movable physical object with an unlettered cover. It is 88 × 48 on the left shelf, shrinks to a closed 64 × 36 silhouette while carried, and becomes a 138 × 164 portrait cover when placed on the right desk; the full-size cloth cover is original deterministic Canvas geometry. Placement keeps the cover closed. On the right desk, its lower-right folded corner opens a 276 × 164 spread on the right desk. Eight paper spreads explain admission, job-specific examination profiles, stamps, handoff, notes, storage, correspondence, timing, keyboard controls and life after work. Financial guidance deliberately omits exact probabilities, charges and insurance formulas. Their smaller folded corners use 9-pixel artwork and aligned 13 × 12 semantic targets derived from the same size constant, without arrow or X symbols; the first backward turn returns to the cover. Enter toggles the focused book, and Escape closes an open book before leaving the cabinet. Corner hit areas follow position and stacking, remain keyboard accessible, and are absent while carrying the book or storing it on the left. Enter on the left book retains the shortcut to open it on the right desk. Page text and announcements are localized and measured in the compact document font. Opening or turning a page costs one minute. The book is not a modal and can overlap paperwork like another desk item.

Patient entry and exit each use 12 frames advanced every 60 ms outside drawing.
