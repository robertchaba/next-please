# Technical guidelines

Established game-world facts and open questions live in [FACTS.md](../FACTS.md); keep technical details and implementation status in these guidelines or the README. Follow [the art direction](art-direction.md) for creative guidance, including its constraints on explicit dates and locations in visible and accessible interface text.

## Runtime and tooling

Next, Please! is a browser-only, client-side game. Vite and strict TypeScript produce static HTML, CSS, JavaScript, and local assets. There is no backend, account system, runtime API, CDN dependency, or remotely loaded font. The browser supplies Canvas 2D, file selection/download, and fullscreen support. Outside the game canvas, the page uses system monospace fonts.

Use Node 22.12+ on the Node 22 release line, Node 24, or Node 26+ to satisfy the current tooling. Install from the committed lockfile with `npm ci`. Keep runtime dependencies focused: `fflate` handles save compression; Howler handles local music and effects. Add libraries only when they solve an actual game requirement.

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the local development server. |
| `npm run build` | Type-check, then create the static `dist/` build. |
| `npm run preview` | Serve that build locally. |
| `npm test` | Run Vitest unit checks. |
| `npm run test:browser` | Run Playwright interface checks. |

## Display and input

- The canvas and its logical coordinate system are always **570 × 320**. Keep layout positions, hit areas, text, and sprite coordinates in native pixels.
- Use Canvas 2D with image smoothing disabled. Use `image-rendering: pixelated` for display scaling. Do not increase the canvas backing resolution to match the window or device pixel ratio.
- `src/core/display.ts` chooses a whole-number CSS scale when the available space permits at least 1×. Center the frame and leave unused space around it rather than stretching its aspect ratio. Fullscreen follows the same rule.
- There is no text row above the frame. The lower row uses a 16px container (14px on small screens), compact 12px utility labels, 14px PL / EN buttons, and native DOM controls. Measure its actual wrapped height when fitting the frame, including fullscreen; language changes must also trigger fitting.
- Below native resolution, fractional fitting keeps the interface visible. Uneven or lost pixels are unavoidable at this size. Browser zoom and fractional device pixel ratios can also affect physical pixel alignment.
- Canvas-rendered controls have transparent semantic DOM buttons or links over the same native rectangles. Preserve keyboard focus, accessible names, tab order, and visible focus indicators. Keep these in-scene DOM controls and canvas inside the same scaled stage. Language, fullscreen, music, and cabinet menu/save controls live outside the stage in the lower page row. Utility controls remain visible in fullscreen; paper dialogs make them inert until closed.
- `src/render/font.ts` is the original bitmap font, with Polish diacritics. Glyph cells are 5 × 9, ordinary capitals use the bottom seven rows, spaces are three pixels wide, and the gap between characters is one pixel. Multiline advance is twelve pixels. The separate document face preserves mixed case with a five-pixel lowercase x-height, variable-width glyphs, Polish accents, and eleven-pixel line advance. Use `drawDocumentText`/`measureDocumentText` for paperwork and the rulebook, retaining the established title face. Measure text before placing it; never scale a label fractionally to make it fit.
- The pixel cursor is generated locally in `src/core/display.ts`; keep a browser cursor fallback.

## State, scenes, and localization

Version 0.2 includes the title screen, credits, preferences, a four-card illustrated introduction, a playable three-patient cabinet shift, and progress import/export. Start enters the introduction; later visits to the menu offer Resume. The office initially has no patient. The cabinet has four physical areas separated at x = 282–287 and y = 128–137: two 282 × 128 room views above two 282 × 182 desktop areas. These separators are part of the artwork, with no section captions.

Pure transitions and deterministic patient fixtures live in `src/core/game.ts`; `src/scenes/shift.ts` presents them; `src/render/clinic.ts` draws original illustrations and the office. `src/core/desk.ts` owns pure item-position and stacking-order helpers; `src/core/desk-input.ts` translates mouse, touch, and keyboard input into logical-pixel movement. `src/main.ts` owns scene transitions, temporary selected and carried items, desk layout, typed-text and patient-animation updates, and DOM integration. Keep scene transitions, simulation state, input handling, and drawing separate. Render from current state; drawing must not change game state, call `Date.now()`, or generate new random values. Advance time and randomness during explicit updates, and retain any values needed for reproducible saves. Avoid a framework or general scene engine until concrete scenes need it. The analog clock takes persisted `clockMinutes` (07:57 arrival, 08:00–14:00 action-based shift) and draws plain hands and ticks without work-hours markings. Three cases condense the six-hour day; repeated examinations, corrected stamps, decoration changes, item movement, and patient animations consume no extra simulated time. See the save contract for exact time transitions.

Polish is the default locale; English is equally supported. All user-facing text, accessible names, status messages, and errors belong in the typed dictionaries in `src/i18n.ts`. Keep both languages' keys and meaning aligned. Render the same artwork for both locales, with text drawn separately. Check Polish diacritics and the longest labels at native resolution.

Only locale, mute, and music volume preferences use `localStorage`. Music volume defaults to 40%; missing or invalid stored volume falls back to that default. Volume and mute remain independent. Storage may be blocked or unavailable, so preference reads and writes must remain optional. Gameplay progress is an explicit export/import operation, not browser storage.

## Portable saves

`src/core/save.ts` owns the versioned gzip JSON format and file operations. `fflate` compresses version 3 saves into `.npsave` files. See [save-format.md](save-format.md) for the envelope, limits, error codes, and migration rules.

Treat imports as untrusted data. Validate the entire file before replacing live state; failed imports must preserve the current state, including the temporary desk layout and patient motion. A successful import restores the saved appointment, resets item positions and stacking order, and clears carried items, selected tools, and patient animation. Keep stable error codes in the save layer and translate their presentation in the interface. Export plain game data only: no DOM nodes, audio objects, functions, or temporary presentation state. Dragging and patient animation leave the version 3 schema unchanged. Introduce an explicit migration when gameplay changes the save schema.

## Art and audio

Use the original generated title art documented in [art-direction.md](art-direction.md). The game draws inspiration from bureaucratic satire and period institutions; its art, characters, interface details, and writing must remain original. Do not import assets extracted from existing games or copy their proprietary characters or branding. The pixel font and cursor are project code.

Howler in `src/core/audio.ts` plays the fourteen local MP3s registered by `src/core/music.ts` as a repeating playlist. Music belongs to the application, so title, introduction, panel, and cabinet transitions share uninterrupted playback. Put source MP3s in `public/assets/audio/music/` and sound effects in `public/assets/audio/`; resolve manifest URLs through `import.meta.env.BASE_URL`. Registration and playlist preparation must not autoplay or download audio. The application starts muted unless the user saved another preference; unlock and begin playback only from an unmuted click or key press. The external previous/next buttons wrap the playlist, stop the old track, and preserve mute. Before playback starts, they change only the selected track without loading audio. Muting silences an active playlist without resetting it. Maintain separate music and effect volumes. Skip missing/undecodable playlist tracks, stop after all tracks fail, and report playback failure with a localized message; a later gesture can retry. Keep the manifest and both localized credit lists aligned with the source folder; `tests/music.test.ts` checks for missing, renamed, or unregistered MP3s.

For acquired audio or other third-party assets, record the title, author, source URL, license and license URL, required attribution, and modifications alongside the files. Verify permission for redistribution and the intended game use. Download approved files into the repository; do not hotlink them. User-provided files also need provenance recorded before distribution. See [the audio notes](../public/assets/audio/README.md).

Music controls use original muted-olive SVG icons and semantic DOM buttons outside the canvas. The native range input supports pointer dragging, arrow keys, and Home/End. Its 0–100% value updates Howler and preferences without toggling mute. The speaker's three DOM meter bars use seven height levels sampled from a Web Audio analyser on Howler's existing master mix. The analyser is a side branch with no extra connection to the output. Sample at most ten times per second while the page is visible. Muting, zero volume, loading, and stopped playback leave the indicator still. Reduced motion and HTML audio fallback use a static playing indicator. Localize the speaker's playback description without repeatedly announcing individual meter changes.

## Verification and deployment

Use Vitest for save round-trips, invalid imports, size limits, scaling behavior, and desktop movement bounds. Use Playwright for language switching, accessible controls, credits, save import/export, viewport changes, the illustrated intro, complete cabinet shifts, clock progression, decoration persistence, patient entry/exit, mouse/touch/keyboard item movement, and audio decode/mute. Check reduced motion, aligned moved hotspots, stamp/return guards, and preservation of the live desktop after failed imports. Use Vitest for pure gameplay guards, scoring, action-based time, and nested save validation/migration as well. Add checks for meaningful behavior, not copies of the implementation. Run `npm run build` with the relevant tests before considering a change complete.

Deploy the contents of `dist/` to an HTTP(S) static host. Vite uses `base: './'` to support hosting under a subpath; resolve asset URLs accordingly. No server-side application or secrets belong in this project. Development and built output require a static server; double-clicking the source `index.html` is not a supported launch method. An offline cache or service worker is not part of the current foundation.

## Cabinet input and effects

Canvas-rendered items have aligned semantic buttons. The document, both rubber stamps, rulebook, cup, and pencil can be picked up, moved, and dropped with mouse or touch. Keyboard users focus an item with Tab, lift it with Space, move it with arrows, drop it with Enter or Space, and cancel with Escape. Arrows move four logical pixels, or twelve with Shift. Pointer capture keeps a drag attached to its item; cancellation restores its prior position and stacking order. Clamp complete items to the desktop and round positions to integer logical pixels. Move the semantic rectangles and their stacking order with the artwork, preserving focus and localized pickup/drop instructions in both dictionaries. Item positions, order, and carrying state are temporary presentation data.

Selecting a rubber stamp sets temporary UI tool state; applying it to the certificate invokes a game action. Dropping a stamp on the document uses the same action and guards as click/keyboard activation. Moving a referral from the tray onto the desk takes it; dropping a desk document back into the tray returns it only if stamped. Examinations require a referral on the desk, both results are required before stamping, and a rejected return restores the document's position. The rulebook can be opened at any point and restores focus when closed. The lamp and plant/certificate are interactive hotspots with visible focus and localized accessible names. Visible cabinet lettering is confined to paperwork and the eye chart; the room's 04 plate is drawn as original pixel geometry. Test results, patient details, current time, and action feedback also have a semantic description and localized live announcements. No gameplay progress goes into browser storage.

Patient entry and exit each use six supplied poses, advanced every 140 ms outside drawing. Entry follows a successful call, and exit follows a returned document; queued motion preserves their order. Pause these updates while the document is hidden or a panel covers the cabinet. Reduced motion skips the transition, including when enabled during playback. Returning to the menu clears motion. The renderer only reads the supplied patient ID, direction, and frame; the doorway, shadow, and patient pose change together without changing gameplay progress.

`src/core/effects.ts` registers four original local WAVs produced by `scripts/generate-effects.mjs`. Typewriter reveal updates run outside rendering at 55 ms per character, pause when hidden, stop on scene exit, and skip animation under reduced motion. Each card has only a Next action, available during typing; the fourth goes directly to the cabinet. There are no reveal or skip controls. Screen readers always receive the complete sentence. Load/play effects only after an unmuted user gesture; muted reveal does not request the WAVs. Stamp and paper sounds accompany successful item actions. See the audio notes for synthesis provenance.
