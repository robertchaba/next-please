# Technical guidelines

Established game-world facts and open questions live in [FACTS.md](../FACTS.md); keep technical details and implementation status in these guidelines or the README. Follow [the art direction](art-direction.md) for creative guidance, including its constraints on explicit dates and locations in visible and accessible interface text.

## Runtime and tooling

Next, Please! is a browser-only, client-side game. Vite and strict TypeScript produce static HTML, CSS, JavaScript, and local assets. There is no backend, account system, runtime API, CDN dependency, or remotely loaded font. The browser supplies Canvas 2D, file selection/download, and fullscreen support. Outside the game canvas, the page uses system monospace fonts.

Use Node 22.12+ on the Node 22 release line, Node 24, or Node 26+ to satisfy the current tooling. Install from the committed lockfile with `npm ci`. Keep runtime dependencies focused: `fflate` handles save compression; Howler handles local music and effects. Add libraries only when they solve an actual game requirement.

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the local development server. |
| `npm run build` | Type-check, then create the static `dist/` build. |
| `npm run preview` | Serve that build locally. |
| `npm test` | Run Vitest unit checks. |
| `npm run test:browser` | Run Playwright interface checks. |

## Display and input

- The canvas and its logical coordinate system are always **570 × 320**. Keep layout positions, hit areas, text, and sprite coordinates in native pixels.
- Use Canvas 2D with image smoothing disabled. Use `image-rendering: pixelated` for display scaling. Do not increase the canvas backing resolution to match the window or device pixel ratio.
- `src/core/display.ts` chooses a whole-number CSS scale when the available space permits at least 1×. Center the frame and leave unused space around it rather than stretching its aspect ratio. Fullscreen follows the same rule.
- There is no text row above the frame. The lower row uses a 16px container (14px on small screens), compact 12px utility labels, 14px PL / EN buttons, and 16px Menu / Saves buttons, and native DOM controls. Measure its actual wrapped height when fitting the frame, including fullscreen; language changes must also trigger fitting.
- Below native resolution, fractional fitting keeps the interface visible. Uneven or lost pixels are unavoidable at this size. Browser zoom and fractional device pixel ratios can also affect physical pixel alignment.
- Canvas-rendered controls have transparent semantic DOM buttons or links over the same native rectangles. Preserve keyboard focus, accessible names, tab order, and visible focus indicators. Keep these in-scene DOM controls and canvas inside the same scaled stage. Language, fullscreen, music, and cabinet menu/save controls live outside the stage in the lower page row. Utility controls remain visible in fullscreen; paper dialogs make them inert until closed.
- `src/render/font.ts` is the original bitmap font, with Polish diacritics. Glyph cells are 5 × 9, ordinary capitals use the bottom seven rows, spaces are three pixels wide, and the gap between characters is one pixel. Multiline advance is twelve pixels. The separate document face preserves mixed case in an eight-pixel cell, with six-pixel capitals, a four-pixel lowercase x-height, variable-width glyphs, Polish accents, and nine-pixel line advance. Use `drawDocumentText`/`measureDocumentText` for paperwork and the rulebook, retaining the established title face. Measure text before placing it; never scale a label fractionally to make it fit.
- The pixel cursor is generated locally in `src/core/display.ts`; keep a browser cursor fallback.

## State, scenes, and localization

Version 0.2 includes the title screen, credits, preferences, a four-card illustrated introduction, a playable three-patient cabinet shift, and progress import/export. Start enters the introduction; later visits to the menu offer Resume. The office initially has no patient. The cabinet has four physical areas separated at x = 204–209 and y = 128–137: a 204-pixel left side for the patient and exchange shelf, and a 360-pixel right side for examinations and the main desk. The lower desktop areas are 182 pixels high. These separators are part of the artwork, with no section captions.

Pure transitions and deterministic patient fixtures live in `src/core/game.ts`; `src/scenes/shift.ts` presents them; `src/render/clinic.ts` loads and composites the local generated illustrations, cabinet, and sprites. `src/core/desk.ts` owns pure item-position and stacking-order helpers; `src/core/desk-input.ts` translates mouse, touch, and keyboard input into logical-pixel movement. `src/main.ts` owns scene transitions, temporary selected and carried items, desk layout, typed-text and patient-animation updates, and DOM integration. Keep scene transitions, simulation state, input handling, and drawing separate. Render from current state; drawing must not change game state, call `Date.now()`, or generate new random values. Advance time and randomness during explicit updates, and retain any values needed for reproducible saves. Avoid a framework or general scene engine until concrete scenes need it. The analog clock takes persisted integer `clockMinutes` (07:57 arrival, 08:00–14:00 shift limits). Handling, page turns, stamps and decorative actions cost one minute; vision and pressure tests cost three and four minutes, including repeated tests. Returning a certificate costs one minute. The three-case roster no longer stretches to fill six hours. A temporary 800 ms transition supplies fractional display time to the plain hour, minute and seconds hands; it pauses when hidden or covered, and reduced motion shows the saved time immediately. Pointer movement, waiting, patient movement and speech consume no simulated time. See the save contract for exact time transitions.

Polish is the default locale; English is equally supported. All user-facing text, accessible names, status messages, and errors belong in the typed dictionaries in `src/i18n.ts`. Keep both languages' keys and meaning aligned. Render the same artwork for both locales, with text drawn separately. Check Polish diacritics and the longest labels at native resolution.

Only locale, mute, and music volume preferences use `localStorage`. Music volume defaults to 40%; missing or invalid stored volume falls back to that default. Volume and mute remain independent. Storage may be blocked or unavailable, so preference reads and writes must remain optional. Gameplay progress is an explicit export/import operation, not browser storage.

## Portable saves

`src/core/save.ts` owns the versioned gzip JSON format and file operations. `fflate` compresses version 4 saves into `.npsave` files. See [save-format.md](save-format.md) for the envelope, limits, error codes, and migration rules.

Treat imports as untrusted data. Validate the entire file before replacing live state; failed imports must preserve the current state, including the temporary desk layout, patient movement and speech. A successful import restores the saved appointment, resets item positions, stacking order and the book page, and clears carried items, selected tools, clock interpolation, patient movement and speech. Keep stable error codes in the save layer and translate their presentation in the interface. Export plain game data only: no DOM nodes, audio objects, functions, or temporary presentation state. Version 4 keeps the fields but changes the time contract to small action costs. Versions 1–3 retain strict legacy validation before explicit migration. Earlier clocks are preserved; subsequent actions use the new costs. Item coordinates, open book/page, selected tools, clock interpolation, patient movement and speech are presentation state, not save fields.

## Art and audio

Use the original generated artwork documented in [art-direction.md](art-direction.md). The approved title image is the visual reference for the cabinet, introduction, patients, and tools. These illustrations are made with the built-in image generator and stored locally, with source images and prompts retained. The cabinet background is `public/assets/art/cabinet-corridor.png`; the four `intro-{scalpel,catheter,pen,stamp}.png` illustrations and cabinet background are prepared at 570 × 320. Transparent sprites are prepared from `clinic-sprites-source.png` as individual local assets; the mechanical stamp pair comes from `mechanical-stamps-compact-source.png`. `scripts/prepare-clinic-art.mjs` also runs `prepare-corridor-art.mjs`, which preserves the original lower desktop artwork, composites the generated desk bell, prepares the revised rooms from `cabinet-shadow-source.png` directly at their final viewport positions, and runs `prepare-stamp-art.mjs`. The upper rooms contain a dark patient alcove and examination wall, without an additional desk or couch. The ceiling lamp hotspot is (357,10), 43 × 31; the left desktop bell is (127,170), 44 × 40. The room number is drawn at (174,20). Preserve generated alpha and nearest-neighbor rendering. Composite dynamic patients and tools over the background, then draw the cloth book cover, folded corners, speech balloons, localized text, the 04 plate, and clock hands separately; no localized words belong in generated artwork. The game draws inspiration from bureaucratic satire and period institutions; its art, characters, interface details, and writing must remain original. Do not import assets extracted from existing games or copy their proprietary characters or branding. The pixel font and cursor are project code.

Howler in `src/core/audio.ts` plays the fourteen local MP3s registered by `src/core/music.ts` as a repeating playlist. Music belongs to the application, so title, introduction, panel, and cabinet transitions share uninterrupted playback. Put source MP3s in `public/assets/audio/music/` and sound effects in `public/assets/audio/`; resolve manifest URLs through `import.meta.env.BASE_URL`. Registration and playlist preparation must not autoplay or download audio. The application starts muted unless the user saved another preference; unlock and begin playback only from an unmuted click or key press. The external previous/next buttons wrap the playlist, stop the old track, and preserve mute. Before playback starts, they change only the selected track without loading audio. Muting silences an active playlist without resetting it. Maintain separate music and effect volumes. Skip missing/undecodable playlist tracks, stop after all tracks fail, and report playback failure with a localized message; a later gesture can retry. Keep the manifest aligned with the source folder; `tests/music.test.ts` checks for missing, renamed, or unregistered MP3s.

The credits page uses general contributions: Robert Chaba with his GitHub link, Codex and OpenAI models for programming, and Suno for music. Do not list individual tracks, illustrations, or other assets in the player-facing credits. Keep detailed provenance and redistribution terms in the dedicated asset documentation.

For acquired audio or other third-party assets, record the title, author, source URL, license and license URL, required attribution, and modifications alongside the files. Verify permission for redistribution and the intended game use. Download approved files into the repository; do not hotlink them. User-provided files also need provenance recorded before distribution. See [the audio notes](../public/assets/audio/README.md).

Music controls use original muted-olive SVG icons and semantic DOM buttons outside the canvas. The native range input supports pointer dragging, arrow keys, and Home/End. Its 0–100% value updates Howler and preferences without toggling mute. The speaker's three DOM meter bars use seven height levels sampled from a Web Audio analyser on Howler's existing master mix. The analyser is a side branch with no extra connection to the output. Sample at most ten times per second while the page is visible. Muting, zero volume, loading, and stopped playback leave the indicator still. Reduced motion and HTML audio fallback use a static playing indicator. Localize the speaker's playback description without repeatedly announcing individual meter changes.

## Verification and deployment

Use Vitest for save round-trips, invalid imports, size limits, scaling behavior, and desktop movement bounds. Use Playwright for language switching, accessible controls, credits, save import/export, viewport changes, the illustrated intro, complete cabinet shifts, clock progression, decoration persistence, patient entry/exit, mouse/touch/keyboard item movement, and audio decode/mute. Check reduced motion, aligned moved hotspots, click-to-carry behavior, dedicated tool rests, early stamps, unstamped return rejection, and preservation of the live desktop after failed imports. Use Vitest for pure gameplay guards, scoring with incomplete examinations, action-based time, and nested save validation/migration as well. Add checks for meaningful behavior, not copies of the implementation. Run `npm run build` with the relevant tests before considering a change complete.

Deploy the contents of `dist/` to an HTTP(S) static host. Vite uses `base: './'` to support hosting under a subpath; resolve asset URLs accordingly. No server-side application or secrets belong in this project. Development and built output require a static server; double-clicking the source `index.html` is not a supported launch method. An offline cache or service worker is not part of the current foundation.

## Cabinet input and effects

Canvas-rendered items have aligned semantic buttons. Click or tap once to pick up a document, rubber stamp, or rulebook; the next click uses or places it. The carried item follows the pointer without holding a button, and the cursor is hidden over the stage. The left shelf shows compact papers and a closed book; held items use their full footprint, while documents and the open book occupy the larger right desk. Stamps have small dedicated rests at the far right and stay in hand after an impression or missed attempt. Cup and pencil are absent. Hover and selection add no object outlines; the semantic DOM retains a keyboard-only focus indicator.

Keyboard users focus an item with Tab, lift it with Space, move it with arrows, use or place it with Enter or Space, and cancel with Escape. Arrows move four logical pixels, or twelve with Shift. Enter also retains focused item actions. The patient has a semantic certificate-handoff control; a carried document can be given through it by keyboard. Held objects can travel throughout the viewport, including over the patient; released items are clamped to one desktop with the appropriate footprint. Cancellation restores the prior position, open-book state and stacking order. Hit areas and stacking follow the same integer geometry as the artwork. Pickup and placement spend small amounts of time; pointer movement does not.

Moving the referral out of the tray takes it. Once taken, the paper may be set down on either side. Only handing a stamped certificate to the patient's upper-left portrait ends the visit; the tray is storage. An unstamped handoff restores the document's previous position and keeps the visit active. Examinations require a referral taken from the tray, but either stamp may be applied before tests. A return with missing examinations or an incorrect decision counts as an error with no bonus; a correct decision with both tests complete earns ten points. The lamp and plant/certificate remain interactive, with localized feedback. No gameplay progress goes into browser storage.

The rulebook is a movable physical object with an unlettered cover. It is 88 × 48 on the left shelf and a 138 × 164 portrait cover while carried or placed on the right desk; the full-size cloth cover is original deterministic Canvas geometry. Placement keeps the cover closed. On the right desk, its lower-right folded corner opens a 276 × 164 spread on the right desk. Five paper spreads explain admission, tests, stamps, handoff, timing and keyboard controls. Their folded corners are part of the artwork, without arrow or X symbols; the first backward turn returns to the cover. Enter toggles the focused book, and Escape closes an open book before leaving the cabinet. Corner hit areas follow position and stacking, remain keyboard accessible, and are absent while carrying the book or storing it on the left. Enter on the left book retains the shortcut to open it on the right desk. Page text and announcements are localized and measured in the compact document font. Opening or turning a page costs one minute. The book is not a modal and can overlap paperwork like another desk item.

Patient entry and exit each use 12 frames advanced every 60 ms outside drawing. The portrait keeps its native head scale and 94-pixel width: it moves 24 pixels out of the dark alcove as its lighting resolves, then lowers 18 pixels into the seated position. Its upper 64 source rows remain at native size; the lower 32 rows extend to the desktop throughout sitting, avoiding a gap below the body. Entry completes in 720 ms. The dark background stays still. The settled portrait and handoff target are (38,32), 94 × 96, ending against the desktop divider. Entry follows a successful call and exit follows a handoff. A new call finishes the previous farewell and clears pending movement before starting the new entrance, so the visible portrait and active paperwork belong to the same patient. Exit adds a 1320 ms stationary pause before reversing the movement, keeping the farewell readable for about 1.5 seconds. Updates pause while hidden or covered by panels. Reduced motion skips movement, including when enabled during playback. Returning to the menu clears the effect. The renderer reads supplied patient, direction and frame values without changing gameplay progress.

Patient speech is brief and appears in a small comic balloon beside the face. Localized prototype phrases cover greetings, yes/no answers and thanks; a mild expletive is available in both dictionaries for later writing. Speech timing and selection live in `src/main.ts`, with complete accessible text announced separately. Timers pause with hidden or covered cabinet views. Speech, farewell holds and movement queues are temporary presentation data and are never exported in saves.

`src/core/effects.ts` registers five original local WAVs produced by `scripts/generate-effects.mjs`. Typewriter reveal updates run outside rendering at 55 ms per character, pause when hidden, stop on scene exit, and skip animation under reduced motion. Each card has only a Next action, available during typing; the fourth goes directly to the cabinet. There are no reveal or skip controls. Screen readers always receive the complete sentence. Load/play effects only after an unmuted user gesture; muted reveal does not request the WAVs. Stamp and paper sounds accompany successful item actions. The mechanical stamp uses a distinct 190 ms local effect with a dense platen impact, metal clack and quiet release; successful patient calls use a 680 ms brass-bell effect, preserving Howler mute and gesture unlocking without new runtime dependencies. See the audio notes for synthesis provenance.
