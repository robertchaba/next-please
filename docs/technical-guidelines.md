# Technical guidelines

Established game-world facts and open questions live in [FACTS.md](../FACTS.md); keep technical details and implementation status in these guidelines or the README. Follow [the art direction](art-direction.md) for creative guidance, including its constraints on explicit dates and locations in visible and accessible interface text.

## Runtime and tooling

Next, Please! is a browser-only, client-side game. Vite and strict TypeScript produce static HTML, CSS, JavaScript, and local assets. There is no backend, account system, runtime API, CDN dependency, or remotely loaded font. The browser supplies Canvas 2D, file selection/download, and fullscreen support. Outside the game canvas, the page uses system monospace fonts.

Use Node 22.12+ on the Node 22 release line, Node 24, or Node 26+ to satisfy the current tooling. Install from the committed lockfile with `npm ci`. Keep runtime dependencies focused: `fflate` handles save compression; Howler handles local music and effects. Add libraries only when they solve an actual game requirement.

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the local development server. |
| `npm run build` | Type-check, then create the static `dist/` build. |
| `npm run preview` | Serve that build locally. |
| `npm test` | Run Vitest unit checks. |
| `npm run test:browser` | Run Playwright interface checks. |

## Display and input

- The desktop game canvas and its logical coordinate system are always **570 × 320**. Keep layout positions, hit areas, text, and sprite coordinates in native pixels. The separate mobile reception below does not resize or run the game canvas.
- Use Canvas 2D with image smoothing disabled. Use `image-rendering: pixelated` for display scaling. Do not increase the canvas backing resolution to match the window or device pixel ratio.
- `src/core/display.ts` chooses a whole-number CSS scale when the available space permits at least 1×. Center the frame and leave unused space around it rather than stretching its aspect ratio. Fullscreen follows the same rule.
- There is no text row above the frame. The lower row uses a 16px container (14px on small screens), compact 12px utility labels, 14px PL / EN buttons, and 16px Menu / Saves buttons, and native DOM controls. Measure its actual wrapped height when fitting the frame, including fullscreen; language changes must also trigger fitting.
- Below native resolution, fractional fitting keeps the interface visible. Uneven or lost pixels are unavoidable at this size. Browser zoom and fractional device pixel ratios can also affect physical pixel alignment.
- Canvas-rendered controls have transparent semantic DOM buttons or links over the same native rectangles. Preserve keyboard focus, accessible names, tab order, and visible focus indicators. Keep these in-scene DOM controls and canvas inside the same scaled stage. Language, fullscreen, music, and cabinet menu/save controls live outside the stage in the lower page row. Utility controls remain visible in fullscreen; credits, archive, restart and drawer dialogs make them inert until closed.
- `src/render/font.ts` is the original bitmap font, with Polish diacritics. Glyph cells are 5 × 9, ordinary capitals use the bottom seven rows, spaces are three pixels wide, and the gap between characters is one pixel. Multiline advance is twelve pixels. The separate document face preserves mixed case in a seven-pixel cell, with five-pixel capitals, a four-pixel lowercase x-height, variable-width glyphs, Polish accents, and eight-pixel line advance. Use `drawDocumentText`/`measureDocumentText` for paperwork and the rulebook, retaining the established title face. Measure text before placing it; never scale a label fractionally to make it fit.
- The pixel cursor is generated locally in `src/core/display.ts`; keep a browser cursor fallback.

## Mobile reception

`src/main.ts` evaluates `detectMobileDevice()` from `src/core/device.ts` once, then lazily imports `src/mobile.ts` and `src/desktop.ts` as their views become needed. A mobile user-agent or User-Agent Client Hints flag, a Mac-identifying multitouch device, or a coarse pointer with no hover on a screen whose short side is at most 1100 and long side at most 1500 selects the mobile route. Keep the device decision for the page lifetime, so rotating a real phone does not reveal the game. In addition, `isMobileViewport(width, height)` selects the reception whenever the browser window is at most 900 CSS pixels wide and its width is at most 85% of its height, regardless of device or pointer. Reevaluate this condition on resize.

The mobile route is a responsive, full-screen DOM reception with a generated 320 × 480 handset illustration. Separate 260 × 132 dialogue and 280 × 260 note canvases composite generated local artwork and localized bitmap text with smoothing disabled. Integer text positions and whole-number overlay enlargement preserve the pixel lettering; overlays shrink only when 1× cannot fit between the controls. The upward speech tail at native (67, 0) follows the handset upper grille at (128, 92), accounting for portrait cover cropping and landscape contain positioning. Clamp the balloon within the space between the toolbar and footer. The handset fills the available mobile scene; compact landscape and portrait layouts keep the controls accessible. Starting in the reception does not import desktop gameplay, its artwork, save handling, or the music manifest. On a desktop, widening the window lazily initializes the game. Thereafter the two DOM roots are retained, with the inactive root hidden and inert; switching views does not reload the page or reset game state or the call. Serialize lazy imports and recheck the current dimensions before activating a view. The desktop canvas and its integer fitting remain unchanged.

`src/mobile.ts` owns the temporary five-step sequence: exchange tone, dialing, greeting, reply, note. Four native **Next** activations advance it; holding a key must not skip through steps. The Polish dialogue is “Przychodnia słucham!” followed by “Praca zdalna? Doktor raczy żartować. Czekamy w placówce”. The final note carries the game title and the desktop requirement. All text, accessible names and English equivalents live in `src/i18n.ts`. The shared original bitmap font supplies the note's muted blue handwriting, with deterministic slant and baseline variation in `src/render/mobile.ts`; generated artwork contains no localized words. Keep complete dialogue text accessible, announce step changes, and move focus to the final note. PL / EN use 64 × 60 native buttons with the title bitmap font at 3×, and Next uses a 224 × 76 button with 4× lettering. The 36 × 36 sound icon uses generated 18 × 18 on/off sprites inside a 64 × 60 semantic button. Show exchange and dialing captions only while muted, with 3× bitmap lettering and localized word wrapping. The untaped note uses 4× title and 3× body handwriting; both dictionaries reflow the full copy into seven lines. Keep the mobile header free of a game title and omit its creator footer; Robert Chaba's credit and link remain in desktop credits and project metadata.

Only existing locale, mute and music-volume preferences are read or written. The call step and all other presentation data stay in memory; the reception creates no game state or save. An already initialized desktop retains its state in memory. The mobile audio manager registers only `phone-tone` and `phone-dial`. An unmuted click or keyboard activation unlocks Howler; enable sound or activate the receiver to hear the initial exchange tone. The one-second tone loops seamlessly; the 3.9-second rotary sound plays once on the dialing step. Stop both effects on mute, hidden pages, `pagehide`, or transition into dialogue and the note. `stopSound(id)` unloads to cancel pending requests; delayed decoding must not replay an old step. No music plays on this route. `setDesktopActive(false)` cancels a carried item back to its prior position, pauses patient/clock/typewriter updates and music, stops effects, and disables global game shortcuts. Loaded music keeps its track position; a pending music load is cancelled and can be retried after a later desktop gesture. Returning restores the prior control focus and refits the desktop; each view rereads preferences when activated. Phone effects stop when its view is deactivated. See [the mobile artwork record](art-mobile-2026-10-25.md) and [audio provenance](../public/assets/audio/README.md).

## State, scenes, and localization

Version 0.5 includes the title screen, credits, preferences, a four-card illustrated introduction, a playable three-patient cabinet shift, and progress import/export. Start enters the introduction; later visits to the menu offer Resume. The office initially has no patient. The cabinet has four physical areas separated at x = 204–209 and y = 128–137: a 204-pixel left side for the patient and exchange shelf, and a 360-pixel right side for examinations and the main desk. The lower desktop areas are 182 pixels high. These separators are part of the artwork, with no section captions.

Pure transitions and deterministic patient fixtures live in `src/core/game.ts`; `src/scenes/shift.ts` presents them; `src/render/clinic.ts` loads and composites the local generated illustrations, cabinet, and sprites. `src/core/desk.ts` owns pure item-position and stacking-order helpers; `src/core/desk-input.ts` translates mouse, touch, and keyboard input into logical-pixel movement. `src/desktop.ts` owns scene transitions, temporary selected and carried items, desk layout, typed-text and patient-animation updates, and DOM integration. Keep scene transitions, simulation state, input handling, and drawing separate. Render from current state; drawing must not change game state, call `Date.now()`, or generate new random values. Advance time and randomness during explicit updates, and retain any values needed for reproducible saves. Avoid a framework or general scene engine until concrete scenes need it. The analog clock takes persisted integer `clockMinutes` (07:57 arrival, 08:00–14:00 shift limits). Handling, page turns, stamps and decorative actions cost one minute; vision, pressure, and body measurement tests cost three, four, and two minutes, including repeated tests. Returning a certificate costs one minute. The three-case roster no longer stretches to fill six hours. A temporary 800 ms transition supplies fractional display time to the hour and minute hands (there is no second hand); it pauses when hidden or covered, and reduced motion shows the saved time immediately. Pointer movement, waiting, patient movement and speech consume no simulated time. See the save contract for exact time transitions.

Polish is the default locale; English is equally supported. All user-facing text, accessible names, status messages, and errors belong in the typed dictionaries in `src/i18n.ts`. Keep both languages' keys and meaning aligned. Render the same artwork for both locales, with text drawn separately, except for the four generated PL/EN decision impressions and the generated eye chart’s fixed optotypes. Decision words also belong in the dictionaries and accessible descriptions. The chart’s six language-independent letter rows are recorded in both dictionaries and baked into the background with their paper and rails, without runtime text overlays; its localized semantic examination control retains its original bounds. See [the eye-chart artwork record](art-eye-chart-2026-10-25.md). Check Polish diacritics and the longest labels at native resolution.

Only locale, mute, and music volume preferences use `localStorage`. Music volume defaults to 40%; missing or invalid stored volume falls back to that default. Volume and mute remain independent. Storage may be blocked or unavailable, so preference reads and writes must remain optional. Gameplay progress is an explicit export/import operation, not browser storage.

## Staff room and archive

The cabinet's Menu button and Escape (after canceling a carried item or closing the book) open the staff-room scene. It pauses clock interpolation, patient motion and speech while keeping the current appointment, placed items, stacking and open book/page in memory. Resume or Escape returns to the same cabinet. Music continues. The room uses the same two-line Next, Please! lettering as the welcome screen, without a visible room caption or explanatory copy. Its accessible description still conveys the scene and pause state. The room offers Resume, Saves, Start over and Credits. Start over opens a keyboard-accessible confirmation with initial focus on cancellation; confirmation creates the initial first-day introduction and clears temporary presentation state while preserving locale, mute and volume. An older pending import is invalidated so it cannot overwrite the new game.

The archive uses a separate medical-secretary scene with Export, Import and Back controls. Opening it from the staff room or restart confirmation returns to that same screen; resuming after an import follows the loaded phase. Save validation and the version 8 format also preserve stored paperwork. Both new scenes have local 570 × 320 artwork, localized text and controls on the quiet left wall (x = 32–240), plus full accessible scene descriptions. Credits, archive and restart confirmation trap keyboard focus and make outside utility controls inert; Escape closes them.

## Portable saves

`src/core/save.ts` owns the versioned gzip JSON format and file operations. `fflate` compresses version 8 saves into `.npsave` files. See [save-format.md](save-format.md) for the envelope, limits, error codes, and migration rules.

Treat imports as untrusted data. Validate the entire file before replacing live state; failed imports must preserve the current state, including the temporary desk layout, patient movement and speech. A successful import restores the saved appointment, resets item positions, stacking order and the book page, and clears carried items, selected tools, clock interpolation, patient movement and speech. Keep stable error codes in the save layer and translate their presentation in the interface. Export plain game data only: no DOM nodes, audio objects, functions, or temporary presentation state. Version 4 introduced small action costs. Version 5 added body measurements and persistent paperwork. Version 6 makes certificate intake explicit with `visit.certificateTaken`. Version 7 adds named certificates, supplementary annotations and paperclip bundles. Version 8 adds the separately stored manual and loose clips in `drawerItems`. Versions 1–7 retain strict legacy validation before explicit migration. Earlier clocks are preserved; subsequent actions use the new costs. Item coordinates, open book/page, selected tools, clock interpolation, patient movement and speech are presentation state, not save fields.

## Verification and deployment

Use Vitest for save round-trips, invalid imports, size limits, scaling behavior, and desktop movement bounds. Use Playwright for language switching, accessible controls, credits, save import/export, viewport changes, the illustrated intro, complete cabinet shifts, clock progression, decoration persistence, patient entry/exit, mouse/touch/keyboard item movement, and audio decode/mute. Check reduced motion, aligned moved hotspots, click-to-carry behavior, dedicated tool rests, early stamps, unstamped return rejection, and preservation of the live desktop after failed imports. Use Vitest for pure gameplay guards, scoring with incomplete examinations, action-based time, and nested save validation/migration as well. Add checks for meaningful behavior, not copies of the implementation. Run `npm run build` with the relevant tests before considering a change complete.

Deploy the contents of `dist/` to an HTTP(S) static host. Vite uses `base: './'` to support hosting under a subpath; resolve asset URLs accordingly. No server-side application or secrets belong in this project. Development and built output require a static server; double-clicking the source `index.html` is not a supported launch method. An offline cache or service worker is not part of the current foundation.

## Civil dates and document marks

`src/core/calendar.ts` derives Gregorian dates purely from the persisted one-based day counter: day 1 is 1983-11-03, and each next shift adds one civil day, including weekends. There is no system clock, timezone, browser locale or new save field in this calculation. The desk calendar uses the current day and shows only the month and day, also in its accessible description; stored papers use their own `day`, preserving full issue dates across later shifts and imports. PL formats dates as DD.MM.YYYY and EN as DD/MM/YYYY; month and weekday labels live in both dictionaries.

`src/render/paperwork.ts` composites generated local seals and an anonymous signature into reserved header/footer space, without a visible signature caption. Referrals use the employer seal, letters/envelopes use their persisted sender's seal, and notes use the clinic seal; certificates select the generated impression for their decision and locale. These are presentation details and do not add authenticity-checking mechanics. The [asset record](art-drawer-documents-2026-10-25.md) retains sources and the offline nearest-neighbor preparation recipe.
