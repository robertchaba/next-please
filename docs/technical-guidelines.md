# Technical guidelines

Established game-world facts and open questions live in [FACTS.md](../FACTS.md); keep technical details and implementation status in these guidelines or the README. Follow [the art direction](art-direction.md) for creative guidance, including its constraints on explicit dates and locations in visible and accessible interface text.

## Runtime and tooling

Next, Please! is a browser-only, client-side game. Vite and strict TypeScript produce static HTML, CSS, JavaScript, and local assets. There is no backend, account system, runtime API, CDN dependency, or remotely loaded font. The browser supplies Canvas 2D, file selection/download, and fullscreen support. Outside the game canvas, the page uses system monospace fonts.

Use Node 22.12+ on the Node 22 release line, Node 24, or Node 26+ to satisfy the current tooling. Install from the committed lockfile with `npm ci`. Keep runtime dependencies focused: `fflate` handles save compression; Howler handles local music and effects. Add libraries only when they solve an actual game requirement.

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the local development server. |
| `npm run build` | Type-check, then create the static `dist/` build. |
| `npm run preview` | Serve that build locally. |
| `npm test` | Run Vitest unit checks. |
| `npm run test:browser` | Run Playwright interface checks. |

## Display and input

- The desktop game canvas and its logical coordinate system are always **570 × 320**. Keep layout positions, hit areas, text, and sprite coordinates in native pixels. The separate mobile reception below does not resize or run the game canvas.
- Use Canvas 2D with image smoothing disabled. Use `image-rendering: pixelated` for display scaling. Do not increase the canvas backing resolution to match the window or device pixel ratio.
- `src/core/display.ts` chooses a whole-number CSS scale when the available space permits at least 1×. Center the frame and leave unused space around it rather than stretching its aspect ratio. Fullscreen follows the same rule.
- There is no text row above the frame. The lower row uses a 16px container (14px on small screens), compact 12px utility labels, 14px PL / EN buttons, and 16px Menu / Saves buttons, and native DOM controls. Measure its actual wrapped height when fitting the frame, including fullscreen; language changes must also trigger fitting.
- Below native resolution, fractional fitting keeps the interface visible. Uneven or lost pixels are unavoidable at this size. Browser zoom and fractional device pixel ratios can also affect physical pixel alignment.
- Canvas-rendered controls have transparent semantic DOM buttons or links over the same native rectangles. Preserve keyboard focus, accessible names, tab order, and visible focus indicators. Keep these in-scene DOM controls and canvas inside the same scaled stage. Language, fullscreen, music, and cabinet menu/save controls live outside the stage in the lower page row. Utility controls remain visible in fullscreen; credits, archive, restart and drawer dialogs make them inert until closed.
- `src/render/font.ts` restores the original bitmap font from `0732752^` (`def5d7f`), including Polish diacritics and exact glyph advances. Title-screen glyph cells are 5 × 9, ordinary capitals use the bottom seven rows, spaces are three pixels wide, and the character gap is one pixel; multiline advance is twelve pixels. The original document alphabet uses seven-pixel cells, five-pixel capitals, four-pixel lowercase, variable-width glyphs, three-pixel spaces and eight-pixel line advance. `drawReadingText`/`measureReadingText` are aliases of `drawDocumentText`/`measureDocumentText`; `face` remains a compatible role argument with no glyph variation. `drawDocumentHeading`/`measureDocumentHeading` use the same restored document glyphs, uppercase text and whole-number scaling. Referrals use ten-pixel field leading and notes fourteen-pixel leading. Distinguish written entries with ink color, never cursive or simulated slant. Measure before placing text; never scale a label fractionally to make it fit.
- The pixel cursor is generated locally in `src/core/display.ts`; keep a browser cursor fallback.

## Mobile reception

`src/main.ts` evaluates `detectMobileDevice()` from `src/core/device.ts` once, then lazily imports `src/mobile.ts` and `src/desktop.ts` as their views become needed. A mobile user-agent or User-Agent Client Hints flag, a Mac-identifying multitouch device, or a coarse pointer with no hover on a screen whose short side is at most 1100 and long side at most 1500 selects the mobile route. Keep the device decision for the page lifetime, so rotating a real phone does not reveal the game. In addition, `isMobileViewport(width, height)` selects the reception whenever the browser window is at most 900 CSS pixels wide and its width is at most 85% of its height, regardless of device or pointer. Reevaluate this condition on resize.

The mobile route is a responsive, full-screen DOM reception with a generated 320 × 480 handset illustration. Separate 260 × 132 dialogue and 280 × 260 note canvases composite generated local artwork and localized bitmap text with smoothing disabled. Integer text positions and whole-number overlay enlargement preserve the pixel lettering; overlays shrink only when 1× cannot fit between the controls. The upward speech tail at native (67, 0) follows the handset upper grille at (128, 92), accounting for portrait cover cropping and landscape contain positioning. Clamp the balloon within the space between the toolbar and footer. The handset fills the available mobile scene; compact landscape and portrait layouts keep the controls accessible. Starting in the reception does not import desktop gameplay, its artwork, save handling, or the music manifest. On a desktop, widening the window lazily initializes the game. Thereafter the two DOM roots are retained, with the inactive root hidden and inert; switching views does not reload the page or reset game state or the call. Serialize lazy imports and recheck the current dimensions before activating a view. The desktop canvas and its integer fitting remain unchanged.

`src/mobile.ts` owns the temporary five-step sequence: exchange tone, dialing, greeting, reply, note. Four activations advance it. Tapping anywhere in the scene also advances, with a one-second cooldown after every advance for scene taps. The native **Next** button bypasses that cooldown; language and sound controls do not advance the call. Holding a key must not skip through steps. The Polish dialogue is “Przychodnia słucham!” followed by “Praca zdalna? Doktor raczy żartować. Czekamy w placówce”. The final note carries the game title and the desktop requirement. All text, accessible names and English equivalents live in `src/i18n.ts`. The shared original bitmap font supplies the note's muted blue handwriting, with upright lettering and a steady baseline in `src/render/mobile.ts`; generated artwork contains no localized words. Keep complete dialogue text accessible, announce step changes, and move focus to the final note. PL / EN use 64 × 60 native buttons with the title bitmap font at 3×, and Next uses a 224 × 76 button with 4× lettering. The 36 × 36 sound icon uses generated 18 × 18 on/off sprites inside a 64 × 60 semantic button. Show exchange and dialing captions only while muted, with 3× bitmap lettering and localized word wrapping. The untaped note uses 4× title and 3× body handwriting; both dictionaries reflow the full copy into seven lines. Keep the mobile header free of a game title and omit its creator footer; Robert Chaba's credit and link remain in desktop credits and project metadata.

Only existing locale, mute and music-volume preferences are read or written. The call step and all other presentation data stay in memory; the reception creates no game state or save. An already initialized desktop retains its state in memory. The mobile audio manager registers only `phone-tone` and `phone-dial`. An unmuted click or keyboard activation unlocks Howler; enable sound to hear the initial exchange tone; tapping the receiver advances to dialing. The one-second tone loops seamlessly; the 3.9-second rotary sound plays once on the dialing step. Stop both effects on mute, hidden pages, `pagehide`, or transition into dialogue and the note. `stopSound(id)` unloads to cancel pending requests; delayed decoding must not replay an old step. No music plays on this route. `setDesktopActive(false)` cancels a carried item back to its prior position, pauses patient/clock/typewriter updates and music, stops effects, and disables global game shortcuts. Loaded music keeps its track position; a pending music load is cancelled and can be retried after a later desktop gesture. Returning restores the prior control focus and refits the desktop; each view rereads preferences when activated. Phone effects stop when its view is deactivated. See [the mobile artwork record](art-mobile-2026-10-25.md) and [audio provenance](../public/assets/audio/README.md).

## State, scenes, and localization

The welcome screen's **O co tu chodzi? / How to play?** action opens a modal `help` screen. `src/render/help.ts` wraps both dictionaries with the original bitmap font and supplies shared paragraph geometry for Canvas text and the native DOM scroll region. The controller installs semantic headings and paragraphs, reads native `scrollTop` and supplies it to drawing; drawing rounds the offset to whole logical pixels and clips only the content area. The header and Back action stay fixed. Native wheel, scrollbar, arrows, Page Up/Down and Home/End work inside the focused region. Focus cycles between the region and Back, outside controls become inert, and Escape or Back restores focus to the initiating link. Reopening starts at the top. Help is presentation only and adds no saved fields. Its copy describes existing gameplay without changing world facts.

The title footer uses the localized **Udostępnij / Share** text button, aligned with its semantic hit area, and the package version with its deterministic codename (see [versioning.md](versioning.md)). `src/core/share.ts` invokes the browser's [Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Share_API) directly from the button gesture, with the exact `window.location.href` captured at activation, a localized title and joke. Share support and `canShare` are checked when available. Unsupported or failed sharing falls back to `navigator.clipboard.writeText`; absent or denied clipboard access offers the address in a localized native text dialog. An `AbortError` cancels silently, without copying. Repeated activation while sharing is pending is ignored and announced with `aria-busy`/`aria-disabled`. Neither the URL nor share state is persisted. There are no social SDKs, third-party scripts, or automatic posts.

The current build includes the title screen, credits, preferences, a four-card illustrated introduction, daily cabinet shifts with 188 characters, illustrated domestic/weekend/departure scenes, and progress import/export. Start enters the introduction; later visits to the menu offer Resume. The office initially has no patient. The cabinet has four physical areas separated at x = 204–209 and y = 128–137: a 204-pixel left side for the patient and exchange shelf, and a 360-pixel right side for examinations and the main desk. The lower desktop areas are 182 pixels high. These separators are part of the artwork, with no section captions.

Pure transitions live in `src/core/game.ts`; the stable case catalog and seeded queue generation live in `src/core/patients.ts`, while `src/core/economy.ts` calculates settlement; `src/scenes/shift.ts` presents them; `src/render/clinic.ts` loads and composites the local generated illustrations, cabinet, and sprites. `src/core/desk.ts` owns pure item-position and stacking-order helpers; `src/core/desk-input.ts` translates mouse, touch, and keyboard input into logical-pixel movement. `src/desktop.ts` owns scene transitions, temporary selected and carried items, desk layout, typed-text and patient-animation updates, and DOM integration. Keep scene transitions, simulation state, input handling, and drawing separate. Render from current state; drawing must not change game state, call `Date.now()`, or generate new random values. Advance time and randomness during explicit updates, and retain any values needed for reproducible saves. Avoid a framework or general scene engine until concrete scenes need it. The analog clock takes persisted integer `clockMinutes` (07:57 arrival, 08:00 opening, 14:00 admissions cutoff and 17:15 final closing). Handling, page turns, stamps and decorative actions cost one minute; general examination, vision, pressure, and body measurement tests cost three, three, four, and two minutes, including repeated tests. Returning a certificate costs one minute. Calls are rejected from 14:00 onward. An admitted patient remains actionable after 14:00 and the clock continues advancing. Crossing 17:00 queues the localized cleaner call and its short balloon. Reaching 17:15 aborts the current action and any unfinished visit, removes the active certificate from clip groups and settles from the preceding state without a patient bonus or decision consequence; existing notes and referrals remain. The saved home clock preserves overtime instead of rewinding to 14:00. Returning the last certificate at closing or queue exhaustion settles the day immediately; the view completes the patient departure before showing home, without a bell activation. Explicit end-day remains available for an empty, finished office. A temporary 800 ms transition supplies fractional display time to the hour and minute hands (there is no second hand); it pauses when hidden or covered, and reduced motion shows the saved time immediately. The independent elapsed clock in `src/core/clock.ts` accumulates monotonic `performance.now()` deltas supplied by the controller: 30 real seconds add 30 simulated minutes with an active visit or 5 without one. The controller samples every 100 ms and at actions/context changes, applying whole minutes through pure `advanceClinicTime`; it retains the fractional remainder across actions, rate switches and pauses. Reading, carrying, pointer movement, patient animation and an open drawer keep the simulation running. Menus, hidden tabs, intro/home and the mobile reception pause it without later catch-up. Reduced motion changes only presentation. New days, restarts and successful imports reset the unsaved sub-minute remainder; failed imports preserve it. Ordinary elapsed ticks update the clock and accessible description without replacing controls or stealing focus. The admission cutoff, cleaner warning and final closing apply equally to elapsed time and action costs. See the save contract for exact time transitions.

Polish is the default locale; English is equally supported. All user-facing text, accessible names, status messages, and errors belong in the typed dictionaries in `src/i18n.ts`. Keep both languages' keys and meaning aligned. Render the same artwork for both locales, with text drawn separately, except for the four generated PL/EN decision impressions and the generated eye chart’s fixed optotypes. Decision words also belong in the dictionaries and accessible descriptions. The chart’s six language-independent letter rows are recorded in both dictionaries and baked into the background with their paper and rails, without runtime text overlays; its localized semantic examination control retains its original bounds. See [the eye-chart artwork record](art-eye-chart-2026-10-25.md). Check Polish diacritics and the longest labels at native resolution.

Only locale, mute, and music volume preferences use `localStorage`. Music volume defaults to 40%; missing or invalid stored volume falls back to that default. Volume and mute remain independent. Storage may be blocked or unavailable, so preference reads and writes must remain optional. Gameplay progress is an explicit export/import operation, not browser storage.

Credits, archive and restart confirmation trap keyboard focus and make outside utility controls inert; Escape closes them.

## Daily queues and settlement

`src/core/patients.ts` keeps 6,193 stable case IDs: 553 historical cases and 5,640 active cases for 940 identities sharing 188 portraits. IDs 0–102 retain their existing details and decisions; IDs 103–302 add eight variants for each of 25 new identities; IDs 303–327 append one general-examination concern for each of those identities. IDs 328–552 add nine cases for each of 25 further identities, without changing any earlier record. Separate catalogs define 48 jobs, 27 employers, 16 exposure tags, six work patterns and three active requirement profiles. Referrals and the manual identify WC/W/C requirements; general examination and body measurements are required in all profiles. A general concern requires refusal unless a matching day-7 report resolves that specific concern; relevant vision/pressure findings otherwise determine the decision. The empty-hand patient control performs the general examination; the same portrait accepts a carried certificate for handoff. Numeric game tuning is explicit in the manual: a vision defect greater than 6 in either eye requires refusal while exactly 6 is discretionary; pressure within ±5 of 160 systolic or 100 diastolic is discretionary, while either value above that band requires refusal. Systolic 180 or diastolic 110 is highlighted red. These are simplified fictional thresholds, not clinical guidance. From working day 4, a specialist certificate for the matching job can waive hypertension only; all other contraindications remain. See [patient-catalog.md](patient-catalog.md) for authoring contracts and deferred requirements. Each working day chooses one identity and case per eligible portrait. `createDailyRoster` excludes pilots, militia officers, miners and steelworkers before working day 7, yielding 168 portraits; from working day 7 the full 188-person cast is eligible. Filtering happens before case selection and balancing, including on day one. Seeded replacements with existing fit variants of the same identity cap unfit patients at floor(33% of the eligible queue), currently 55 of 168 or 62 of 188; adjusting the prefix with fit variants keeps every queue prefix at or below 33% while preserving the recency order. Without admission history, the original seeded fit-patient ordering remains available. Cases and examination criteria remain immutable. This balancing applies only to newly generated queues, not imported rosters; the second patient on working day 6 is a scripted exception. New queues prioritize unseen portraits, then those seen longest ago, based on actual admissions retained across days and save files. The constructor accepts an explicit seed for replay/tests and otherwise obtains fresh crypto entropy outside rendering. `GameState.roster` and `rngState` persist; drawing and accessible descriptions do not generate randomness. Old saves preserve their exact 28-, 53- or 78-person queue until the next working day.

`GameState.daily` tracks detected ZUS cases, employer complaints, fines and insurance increases. An incorrect approval is detected with probability 65%; a healthy refusal is detected with probability 75%, or 97% for managers. Each detected approval adds 100 zł for the first daily case and 400 zł thereafter. Each detected refusal raises the persistent insurance rate by 50 zł at the 300 zł base, otherwise 100 zł. At settlement, a day with no insurance increase lowers the rate by 50 zł, clamped to 300 zł, before charging that day's premium on paid days; Saturday/Sunday retain the decay but charge zero insurance.

Returning a certificate after closing or queue exhaustion settles the day automatically. Explicit `end-day` is permitted only in an empty office after closing or queue exhaustion. It produces one persisted `DaySettlement` and moves the phase to `home`; repeated settlement actions cannot pay twice. Income is 1000 zł plus 50 zł per returned certificate. Ordinary living costs apply from day one and are inclusive integer draws from 400 to 800 zł, subject to the weekend affordability rule. After wages and ordinary costs, savings over 2000 zł permit an unexpected medicine, fur-coat, car-repair or home-repair expense; probability grows with savings and is capped at 85%. Current probability/cost formulas are implementation tuning in `src/core/economy.ts`, not additional narrative facts. A negative closing balance causes the implemented bankruptcy ending unless the assault ending already takes precedence. Bribes and the hospital ending are implemented from working day 6; relationship-driven events remain deferred.

The home sequence composites generated local backgrounds with enlarged localized typewriter text: arrival, optional saved event, budget and departure before the next workday. Before presenting home, the controller calls pure `settleWeekend` to settle any remaining Saturday/Sunday once, stopping immediately on an ending. Friday through Sunday then show a single arrival card and one combined budget before Monday; imported partial weekends advance only their unsettled days. Budget rows are summed base income, patient bonus, net bribe income when nonzero, the first ledger’s opening balance, summed living costs, fines, insurance, optional combined extra expenses and the closing balance. Negative amounts carry a minus and red ink (#e18b79); zero stays unsigned. Rows use 21, 19 or 17 native pixels of spacing to fit up to nine rows above the action. Label the opening balance “Z poprzedniego dnia” / “From the previous day” for a daily ledger and “Sprzed weekendu” / “Before the weekend” when prior weekend ledgers are included. Event cards omit prices; the budget includes their combined cost without expense formulas. `previousMonthBalance` snapshots the balance when the calendar month changes; old saves initialize the unavailable historical amount to zero. That monthly field remains compatible with old saves but is no longer displayed in the budget. Every home card uses `drawText`, the original welcome-screen face, without enlarging the compact document font. Titles and narrative text use integer 2× scale; budget text, amounts and action use native 1× scale. Home cards omit dates from both canvas and accessible text; the office calendar remains the date reference. Arrival continues with “Dalej” / “Continue”. The twelve arrival and twelve work comments use stable indices from saved `rngState` and day, without drawing randomness or changing state. Budget comments use one of three five-line pools for a positive, negative or zero summarized-period balance change, independently of total savings; repainting, changing language and importing preserve the selected variant. Native-width wrapping keeps narrative lines inside 312 pixels and long amounts clear of budget labels; amounts end at x = 319, leaving more space before the illustration. The current page’s complete text and illustration description remain accessible while it types. Typing state stays outside drawing and saves; reopening a saved settlement starts its presentation at arrival without charging anything again. The home cursor advances every 24 ms with one local typewriter key at most per three characters; the intro retains 55 ms. Enter first reveals the page and then advances; held keys cannot skip cards. Menus/archive preserve the cursor, and reduced motion immediately reveals text. `next-day` is allowed only from home, preserves balance/insurance/paperwork, clears daily consequences, and snapshots monthly carryover on rollover. Weekends produce settled home days with an empty queue, zero wages/bonuses, zero insurance charge and household costs. Before Saturday, draw both ordinary daily costs. If Friday’s closing balance covers their sum, charge those amounts; otherwise charge the remaining Friday–Sunday living allowance of max(0, 800 − Friday living cost), split with the odd zł on Sunday, without a cash cap. Advancing to a rest day appends the prior settlement to `budgetHistory`; Monday clears it. Validation checks each historical ledger, consecutive dates, balance continuity and the Sunday provision; old imports retain only history actually available after loading. Saturday persists `settlement.weekend = { modest, sundayLivingCost }`; Sunday consumes that reservation and retains the mode with zero remaining cost. Optional expenses preserve the Sunday reservation. The required modest living costs can cause bankruptcy on either rest day; a negative settlement ends play immediately, while exactly zero remains playable. The modest mode uses its generated arrival illustration and localized joke; the budget uses the existing weekend illustration. No history is reconstructed in rendering. Its saved expense may be a mountain/seaside trip, with no named destination, at most once per newly settled weekend. Sunday excludes both trip kinds when the immediately preceding Saturday ledger already records a trip; the four ordinary expense kinds remain available. This derives from the saved settlement without a new flag, survives Saturday imports and does not carry over to later weekends. Already settled historical double-trip weekends remain importable without changing their costs. Monday generates a fresh queue of eligible portraits and enters the cabinet at 07:57. Existing paid legacy weekend shifts remain importable. All gameplay state continues to use explicit gzip import/export; only preferences enter localStorage.
